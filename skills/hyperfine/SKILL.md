# hyperfine — CLI の実行時間を比べる

hyperfine
はコマンドを複数回実行して経過時間を比較するベンチマークツール。性能変更の確認や、コマンド・スクリプトの比較に使う。すべての変更で必須ではなく、1回だけの所要時間ならシェルの
`time` で十分なこともある。原因の深掘りにはプロファイラを使う。

## 基本の流れ

1. `hyperfine --version` と `hyperfine --help`
   で、実際に使うバージョンとオプションを確認する。バージョンにより既定値や機能が違うため、手元の
   help を優先する。
2. 基準と候補のコマンド、作業ディレクトリ、入力、出力が同等か確認する。キャッシュ状態も揃える。依頼に実コマンドやパスがなければ、勝手に想定・捏造せず確認する。
3. 実行前に、計測対象と `--setup` / `--prepare` / `--conclude` / `--cleanup`
   の内容・影響をすべて調べる。これらは繰り返し実行されたり状態を変更したりする。ウォームアップと測定回数を含めた実行総数も見積もる。
4. 影響を確認した安全な対象だけを、明示したシェルと有限の回数で測る。
5. 条件、結果、ばらつき、不確実性を報告する。1.21.0
   では比較の基準が最速コマンドになる既定動作にも注意する。

使い方を尋ねられただけなら説明にとどめ、任意のワークロードを実行しない。課金 API
呼び出し、外部への送信、破壊的なクリーンアップ、本番変更は、対象と影響への明示的なユーザー承認が必要。一般的な「計測して」は許可ではない。無害なローカル処理や使い捨ての隔離環境を優先する。システム全体のキャッシュ消去、`sudo purge`、`rm -rf`、広範な
clean
コマンドを既定手順にしない。継承された設定やフックも必要に応じて点検する（fish
の起動設定にも副作用があり得る）。

hyperfine がなければ、勝手にインストール・更新しない。この環境では Devbox
で管理されていることを説明し、環境変更の許可を得る。

## シェルと回数

1.21.0 ではシェルが既定で有効。シェル構文を使わない実行ファイルやスクリプトは
`--shell none`（または `-N`）、POSIX シェル構文は `--shell sh`、fish 構文は
`--shell fish` と明示できる。`-S` は値が必要なので単独で使わない。fish
を指定しても、現在の対話セッションの関数・状態がそのまま使われるわけではない。

`--warmup N` は測定前に各コマンドを N 回実行し、`--runs N` は測定回数を N
回に固定する。たとえば `--warmup 3 --runs 10`
は、各コマンドにつき合計13回実行する。既定では適応的に複数回（1.21.0
では少なくとも10回）測る。短い3回程度の試走だけで小さな差を結論づけない。

ウォームアップはキャッシュを温める。冷起動を測るなら自動的に追加しない。`--prepare`
は各測定の直前、`--setup`
は各コマンドの測定一式の前に一度実行する。状態リセットは対象を限定し、安全を確認する。インクリメンタルビルドとフルビルドなど、異なる仕事を比較しない。

## 例（実行前に内容と出力先を確認）

無害なローカル処理の例。時間は環境により異なる。

```sh
hyperfine --shell none --warmup 1 --runs 5 \
  'sleep 0.1' 'sleep 0.2'
```

スクリプト比較では、以下の `old.sh` / `new.sh`
は説明用のプレースホルダー。実在し、同等の仕事をすることを確認してから実行する。結果を
JSON と Markdown
の両方に保存する例でも、出力先が未使用で安全なパスに置き換えられることを先に確認する（既存レポートを上書きしない）。

```sh
hyperfine --shell none --warmup 2 --runs 10 \
  --export-json bench.json --export-markdown bench.md \
  'bash old.sh' 'bash new.sh'
```

fish の起動時間を測る場合は、fish
を直接対話起動するコマンドを使う。起動設定の副作用を先に確認し、繰り返し実行が安全な場合だけ測る。これは対話起動全体の時間であり、fish
構文を実行するだけの計測とは異なる。

```sh
hyperfine --shell none --warmup 1 --runs 5 'fish -i -c exit'
```

## 結果と注意点

報告には hyperfine
のバージョン、実行コマンド、作業ディレクトリ・入力、シェル、ウォームアップと測定回数、キャッシュ状態、平均時間とばらつき（標準偏差など）、比較対象と結果、レポート保存先を含める。ノイズや外れ値が差を支配するなら「判定不能」とする。わずかな差を速度向上と断定しない。

JSON/Markdown
のエクスポートにはコマンド行が含まれる。引数や出力に秘密情報・認証情報を含めず、レポートを自動で外部へアップロードしない。新しい出力先を選び、上書きを避ける。JSON
の細かな構造はバージョン依存なので、解析前に実際の出力を確認する。

LLM/API の E2E
時間も計測できるが、ネットワーク・サーバーの変動と、繰り返しによる費用に注意する。hyperfine
は TTFT や tokens/sec の専用計測器でも負荷生成器でもない。
