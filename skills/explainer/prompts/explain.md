---

実装をレビューする前に理解するための解説資料を作ってください。短いチャット要約ではなく、保存した
Markdown とビルド済み HTML を納品します。

explainer skill
の通常の資料作成・安全・ペルソナ・図・検証・first-reader・納品手順に従います。長い指示を重複して置き換えず、利用可能な
`explainer/SKILL.md` と参照資料を読みます。

ユーザー指定の対象・重点（あれば優先して解釈）： $ARGUMENTS

対象は次の優先順位で決めます。

1. 明示引数
2. 現在の会話で特定された実装範囲
3. 作業コピーの差分

対象がない、または複数の変更範囲が曖昧なら、履歴やリポジトリ全体から選ばず対象を質問します。jj
管理なら `jj status` / `jj log -r @` / `jj diff` を使い、git
コマンドは使いません。説明準備のために実装・既存テスト・VCS
状態を変更しません。skill が許可する解説資料やペルソナの作成は可能です。

変更の目的と実際のコードを区別して調べ、範囲を絞って説明します。

- 何がなぜ変わったか、どう動くか
- 外から見える変更前後の振る舞い
- コードや会話で根拠づけられる設計・トレードオフ
- 実際に実行したテスト／チェックの結果と未確認事項

ファイル・識別子への参照を添え、skill
の基準に該当するときだけ図を使います。後で人が確認する有用な読み順や箇所を示しますが、レビュー所見や合格判定は作りません。推測を事実と混同せず、未実行チェックを実行済みと書かず、正しさ全般を保証しません。

Markdown と HTML を作り、skill の納品手順に従って関連 HTML を caller の cmux
workspace で開きます。既存の表示手順に従い、cmux
が使えない場合は理由と両方のパスを伝えます。新しいサーバーや外部ブラウザーは使いません。

納品後は終了します。parallel-review、reviewer API、修正、commit、push、PR
を開始しません。「レビュー前」はレビュー実行の許可ではありません。
