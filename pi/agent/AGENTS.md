# Pi Global Agent Instructions

This file provides global instructions for Pi Coding Agent sessions.

## Required Tools (MUST)

These are hard requirements for every agent (Pi and others), not preferences. Canonical shared rule: `claude/rules/required-tools.md`. Do not use the legacy alternatives when the required tool is available.

- MUST use `fd` for file and directory discovery. Do NOT use `find`. Examples: `fd PATTERN`, `fd -e ts`, `fd -t f PATTERN`, `fd -H -I PATTERN`. Exception: POSIX-only environments where `fd` is unavailable.
- MUST use `rg` for text/code search. Do NOT use recursive `grep`.
- MUST use `jq` / `yq` for JSON/YAML inspection and transformation. Do NOT hand-parse with ad-hoc shell when `jq`/`yq` can do it.
- MUST use `ast-grep` for syntax-aware code search and codemods when plain text search may be unsafe.
- MUST use `sd` for simple literal/regex replacements in shell workflows. Use precise edit tools for small source-file edits.
- MUST use `taplo` for TOML formatting and validation.
- MUST use `shellcheck` and `shfmt` for shell script validation and formatting.
- MUST prefer non-interactive, machine-readable commands in automated agent workflows. Do NOT use interactive tools such as `fzf` unless the user explicitly requests them.
- MUST NOT re-read the same vendor bundle (`node_modules/**/dist/*.mjs` 等) or large file across multiple turns in one session; once read, note the relevant API/lines and reuse that instead of reading again. Re-reads compound conversation history and inflate cached input tokens on every subsequent request.

## AI Agent Routing

- **Model budget**: Fugu（Sakana）ペアは `fugu-max`（base）と `fugu-ultra-v2.0`（ultra）。`auto-fugu-model.ts` が Fugu ペア上でのみ base↔ultra を自動切替。`parallel-review` は L1/L2 のみで Codex + Claude の固定2 reviewer（Pi headless）を実行する。未指定および `--level auto` は offline L1 alias。L1 は Codex Sol :xhigh + Opus :high、L2 は Astra :max + Opus :max。Level ごとの timeout は `reviewTimeouts` を参照。長いセッションは `/new` または `/compact` で区切る。
- **Model IDs**: `pi/agent/model-roles.json` is the single source of truth. Skills and runners reference catalog roles, never literal model IDs. Resolve Pi roles with `~/.pi/agent/resolve-model.sh ROLE`; resolve the Cursor Agent role with `--field cursor ROLE` (compatibility only — not used for implementation); list with `--list`; parallel-review tiers with `--review-level N` (`backend<TAB>model<TAB>initial<TAB>retry`, exactly Codex and Claude using `pi`); after editing the catalog run `--apply` to sync `enabledModels` into `settings.json`.
- **Implementation**: Use the `impl` skill (`/skill:impl` in Pi; `/impl` elsewhere) to delegate actively via isolated headless Pi (`run_impl.sh`, role `impl.default`, resolve with `resolve-model.sh impl.default`). Pi prepares the implementation prompt and validates the resulting diff, lint, and tests. Only trivial few-line edits may be done directly. Deprecated alias: `cursor-impl` → same canonical `impl` skill.
- **Complexity (implementation validation)**: Follow the scoped cccc policy in the canonical `impl` skill (`~/.agents/skills/impl/SKILL.md`). Classify by intended retention/deployment, not path; disposable snippets may skip mandatory cccc, durable source (including under `/tmp`) may not. Apply WARNING thresholds to new/AI-added processing and compare existing functions against baseline plus diff; file-wide output is diagnostic, not automatic scope attribution. Preserve tool exit meanings (0 measured/no hard, 1 hard, 2 unverified); required UNVERIFIED is not accepted. Does not replace lint, types, tests, or spec checks.
- **Browser automation**: Prefer `cmux-browser` for routine UI inspection, screenshots, navigation, and form interaction inside cmux when WKWebView capabilities are sufficient. Use Playwright only for Playwright E2E tests, Chromium/cross-browser behavior, viewport/device emulation, network mocking, tracing/video, or CDP-only features; if cmux is unavailable, Playwright may be used as the fallback. Every Playwright invocation must use an isolated session/profile and must not attach to the user's normal Chrome or reuse its profile unless explicitly requested; when using `playwright-cli`, use a named isolated session and close it in the same task. Canonical shared policy: `claude/rules/browser-automation.md`.
- **Web research**: Apply cross-research escalation criteria first; it remains higher priority for code/design/dependency decisions, multi-source verification, recent variable facts, or anticipated contradictions. For a simple fetch from a known public official raw-Markdown URL, prefer ax HTTP/body mode (validate response; fallback to Firecrawl on failure/non-Markdown). General search/discovery, unknown URLs, JS, scraping/crawling, and multi-page research use `firecrawl` (`/skill:firecrawl`; sourced from `skills/firecrawl-cli`); use `firecrawl-agent` for structured JSON or autonomous multi-page extraction. These are linked into `~/.agents/skills/` via `scripts/build_env/list_shared_agent_skills.sh`.
- **Web research double-check**: Use `cross-research` (`/skill:cross-research`) for important research that needs verification; it runs Firecrawl, `agy` (Antigravity CLI, successor to Gemini CLI), and Grok X Search in parallel. Use `antigravity-research` (`/skill:antigravity-research`) only for agy-only broad summaries where facts are not treated as confirmed.
- **Review**: For plain 「レビューして」 (an actual review request in the turn—not a quote or discussion), load `parallel-review` and execute immediately after preflight. Parallel review always runs exactly two isolated Pi headless reviewers: Codex and Claude. Unspecified level and `--level auto` are offline L1 aliases; only numeric levels 1/2 are accepted explicitly (3..5 are rejected). The catalog is authoritative for model IDs: L1 uses Codex Sol :xhigh + Opus :high; L2 uses Astra :max + Opus :max. No Jev/OpenRouter routing, routing context, API key, runtime caller, or other provider is involved in parallel review. Send only the secret-screened patch/chunks and configured retry attempts to the two selected reviewers. Stop and ask if credentials, customer data, or employer-confidential material may be present, or if permission is refused, revoked, or restricted; never silently switch providers. Do not broaden permission to unrelated API sends, email, messages, hooks, or arbitrary tasks. Reviewers run through `run_pi_review.sh`; each gets one retry after failure or timeout. Timeouts are L1 600/600s and L2 600/900s (initial/retry). Pi child reviewers disable skills/context to prevent recursive review spawning. Use a single-reviewer skill only when named (`codex-review`, `claude-review`, `grok-review`, `fugu-review`, `muse-review`).
- **MCP integrations**: Use `mcp-delegate` (`/skill:mcp-delegate`) for Slack links and other hosted OAuth MCP workflows (Slack, Sentry, Notion, etc.). It delegates to Claude Sonnet with a connection gate and read-only hardening. Sentry issue workspace flow is still covered by `jj-workspace` (`/skill:jj-workspace`). Do not scrape private Slack URLs with Firecrawl/browser.
